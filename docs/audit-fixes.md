# Исправления аудита — модель 0.2.0

Проверка исходного `main` на коммите `8b09b76` выявила воспроизводимые ошибки
расчёта провиса, допустимости свободной траектории, статуса результата,
ориентации составных STL и разрешения по времени. Все перечисленные случаи
теперь проверяются автоматическими регрессиями.

## Что изменилось

- Общий расчёт пути в `yarnstand/paths.py` использует цепную линию с весом на
  единицу длины самой нити. Он проверен независимо через дифференциальное
  равновесие `H*z'' = lambda*g*sqrt(1+z'^2)`. Старая формула использовала
  плотность на длину нити как нагрузку на горизонтальную проекцию.
- В новых пресетах `unwind_radius_ratio=1` вместо 0.85. Точка схода лежит на
  поверхности горизонтального сечения эллипсоида; для разных полуосей теперь
  используется сам эллипс. Старые импортированные параметры не подменяются.
  Выход внутри клубка или вход пространственной нити в него получает отдельный
  статус, а не результат «свободно». Автоматическое перемещение точки схода
  и огибание клубка по поверхности остаются вне модели.
- Контакт, недопустимый или неопределённый номинальный путь отменяют общий
  положительный статус. Интерфейс отмечает все силы как условные. Механические
  события и их времена сохранены отдельно: одиночная проверка пути не позволяет
  выдумать время первого контакта.
- Для каждой связной оболочки STL проверяются замкнутость, ориентация и
  положительный объём. Составные детали проверяются как объединение объёмов.
  Вложенные отрицательные оболочки полостей явно отклоняются как неподдерживаемые;
  автоматический переворот нормалей мог бы ошибочно заполнить полость.
- Длина импульса подачи интегрируется аналитически. Шаг должен разрешать
  активную часть импульса, движение руки, жёсткость и демпфирование.
  Неразрешённый рывок теперь вызывает ошибку, а не исчезает из расчёта.
- CI устанавливает mesh-зависимости и запускает тесты геометрии и интерфейса.
- Первый полный запуск CI обнаружил дополнительную несовместимость с VTK 9.7:
  настройка допуска через `SetTolerance` перестала действовать для пересечений.
  Кроме того, её поиск всех пересечений пропускает криволинейные поверхности
  даже с явно переданным допуском; это воспроизведено локально на VTK 9.7.1.
  Для VTK 9.7 и новее используется поиск первого пересечения с явным допуском
  `1e-9 м`; для определения факта контакта этого достаточно.
  На более ранних версиях сохранён прежний вызов.
  Регрессия на пересечение сферы проверяет обе версии в локальном и CI-запусках.
  См. [API VTK](https://vtk.org/doc/nightly/html/classvtkOBBTree.html).

## Актуальный пересчёт PITAYA v10

Геометрия изделия не изменялась. Масса, инерция и трение остаются сценарными
оценками. Параметры, хеши исходников и STL находятся в
[metadata.json](../results/pitaya_v10_audit_fix/metadata.json).

| Проверка | Результат |
|---|---|
| 720 номинальных путей, Ø2 мм, 0.04 Н | 456 свободны, 24 касаются деталей, 240 входят в клубок |
| Диаметр / натяжение | 54 случая с сохранёнными исходными параметрами |
| 60 динамических сценариев | 30 нарушают сцепление; 20 имеют недопустимый путь через клубок, ещё 2 — контакт в грубом экране |
| Общий статус динамики | 20 сценариев проходят применяемые проверки; это не проверка всех движущихся петель |
| 24 заданных движения руки | 14 свободны, 2 с начальным контактом, 8 отклонены из-за входа нити в клубок |
| 3 маршрута петли под листом | 2 с контактом, 1 геометрически свободен |

Для полного клубка, выхода из середины и руки сбоку пики теперь около
**0.092 Н** для спиц и **0.203 Н** для крючка. Изменение относительно старых
чисел включает перенос выхода с радиуса 0.85 на наружную поверхность.
Сравнивать прежние и новые цифры как один и тот же набор допущений нельзя.

Старые 696 «свободных» путей нельзя использовать как подтверждение: проверка
не исключала прохождение нити через клубок. Архивный отчёт и исходные данные
сохранены для сравнения, но актуальны результаты в
[pitaya_v10_audit_fix](../results/pitaya_v10_audit_fix).

Проверка CAD-посадок из прежнего отчёта не изменялась: исправления касаются
симулятора и интерпретации его результатов, а не геометрии креплений.

## Воспроизведение

Локально проходят 53 Python-теста (включая STL, без пропусков) и 10 тестов
интерфейса на Node.js. Wheel версии 0.2.0 собран и проверен запуском вне
рабочего каталога. Проверка PEACH v13 также повторена: 3 704 свободных пути,
664 контакта, 4 272 пути через клубок из 8 640; из восьми сохранённых протяжек
четыре свободны и четыре касаются деталей. Подробности — в
[отчёте по персику](peach-v13.md).
Сохранённые полные сетки рассчитаны с VTK 9.6.2 и исходниками основного
исправления `8ef06cc`; точные хеши выполненных файлов записаны в метаданных.
Последующая адаптация вызова для VTK 9.7 не меняет ветвь расчёта на VTK 9.6.

```sh
python -m pip install ".[mesh]"
python -m unittest discover -s tests -v
node --test tests/test_ui.js
python -m yarnstand suite
python -m yarnstand sensitivity
python tools/recheck_pitaya.py /path/to/PITAYA_v10 --out results/pitaya_v10_audit_fix
python tools/recheck_peach.py /path/to/PEACH_v13 --out results/peach_v13_audit_fix
```

Для повторения протяжек персика нужны сохранённые `simulation/sweep_*mm_*.json`
из CAD-комплекта. Скрипт сохраняет переданные позы и их хеши вместе с результатом.
Все пути проверяются геометрически; трение, ворс и самостоятельное скольжение
гибкой нити по препятствию этим не рассчитываются.
